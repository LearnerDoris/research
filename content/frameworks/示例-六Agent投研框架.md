> 用六个独立视角对个股做交叉验证，避免单一视角盲区。已在 [[示例-FCX-2026-Q1]] 等多个案例中应用。

## 六个 Agent

### 1. Orchestrator（协调者）

定义研究问题，分配任务给其他 Agent，最终汇总结论。**输出**：一句话研究问题、Agent 分工。

### 2. Fundamental Analyst（基本面分析师）

财务指标、商业模式、单位经济模型、护城河。**输出**：基本面强弱判断 + 关键 KPI 监控清单。

### 3. Industry Analyst（行业分析师）

行业格局、上下游、技术趋势、竞争对手对照。**输出**：行业 Beta 判断 + 公司在行业中的相对位置。

### 4. Macro Strategist（宏观策略师）

利率、汇率、商品、地缘事件对该公司的传导。**输出**：宏观敏感度评分（高 / 中 / 低 + 方向）。

### 5. Devil's Advocate（魔鬼代言人）

主动反向论证：所有看多逻辑的最坏情景，所有看空逻辑的最坏情景。**输出**：3-5 个最有杀伤力的反向 thesis。

### 6. Risk Officer（风险官）

仓位上限、止损位、对冲方式、监控指标。**输出**：可执行的风控规则文档。

## 标准产出

每次应用产出一份 6 段式 memo：

```markdown
## 1. 基本面
（500 字以内，含 3-5 个数字）

## 2. 行业
（300 字以内，含 1 张行业地图）

## 3. 宏观
（200 字，明确敏感度方向）

## 4. Devil's Advocate
（必须给出至少 3 条反向论证）

## 5. 风险官
（仓位 / 止损 / 监控 三项必填）

## 6. 结论
（确信度 + 操作建议）
```

## 应用案例

- [[示例-FCX-2026-Q1]] — 矿业股完整应用
- HWM（待补） — 工业龙头，最高确信
- TSLA（待补） — 应用结果为 avoid
- PLTR（待补） — hold-watch + 严格仓位上限
- GOOGL（待补） — 科技板块最佳风险回报

## 框架本身的改进

| 版本 | 修订内容 | 触发案例 |
|------|----------|----------|
| v1.0 | 五 Agent（无 Orchestrator） | 早期 |
| v1.1 | 加入 Orchestrator | 发现多 Agent 容易跑题 |
| v1.2 | Risk Officer 必须给硬止损位 | TSLA 案例 |
| v1.3 | Devil's Advocate 至少 3 条 | 减少确认偏误 |
